# Bauhaus UI — 0.2.0dev2

**0.2.0dev2 is unpublished. npm currently installs 0.1.1.** The workspace package version
is `0.2.0-dev.2` on the `Dev` branch; these Storybook 10 docs describe that development
preview. Bau and the native form improvements below are not available from the published 0.1.1 package.

React and ReactDOM peers remain `^18.0.0 || ^19.0.0`, consumer Node remains `>=20`,
and the package supplies ESM, CJS and UMD. Build tooling requires Node 20.19+ or 22.12+;
CI builds on Node 24. React 19 does not ship upstream UMD runtimes: prefer ESM or supply
compatible React/ReactDOM globals yourself when using the library's UMD artifact.

## Install published 0.1.1

```bash
npm install bauhaus-ui-library@0.1.1
```

This basic Button API works with published 0.1.1:

```tsx
import { Button } from 'bauhaus-ui-library'
import 'bauhaus-ui-library/styles.css'

export function App() {
  return <Button color="blue">Build with Bauhaus</Button>
}
```

## Install the unpublished local preview

From a checkout of the `Dev` branch:

```bash
npm ci
npm pack
# In your consumer app, use your actual absolute path:
npm install /absolute/path/to/bauhaus-ui-library-0.2.0-dev.2.tgz
```

Packing builds a local tarball; it does not publish a release. Import `styles.css` once.
Consumers need neither Tailwind nor this site's demo stylesheet.

Try the <a href="./?path=/docs/examples-onboarding--docs" target="_top">installation and native-form examples</a>.
Both have interaction tests; the native form demonstrates required validation, submission,
Switch form values, and reset using the local preview. Their checked-out source is
`src/examples/Onboarding.tsx` and tests are `src/examples/Onboarding.test.tsx`.

## Themes and local portals

```tsx
<section data-bui-theme="dark">
  <Button color="blue">Dark section</Button>
  <div data-bui-theme="light"><Button>Nested light section</Button></div>
</section>
```

Legacy `.dark` remains supported. Public `--bui-*` tokens control the palette, typography,
border width, radius, shadow offset and motion duration. Use the toolbar above to preview
stories in either theme.

Default body portals are SSR safe. To keep a Modal, Drawer, Tooltip or Toast inside a local
theme, pass an actual mounted `portalContainer`. Avoid `document` during SSR render:

```tsx
import { useState } from 'react'
import { Button, Modal } from 'bauhaus-ui-library'

export function LocalTheme() {
  const [host, setHost] = useState<HTMLDivElement | null>(null)
  const [open, setOpen] = useState(false)
  return (
    <section data-bui-theme="dark">
      <Button onClick={() => setOpen(true)}>Open</Button>
      <Modal title="Details" open={open} onClose={() => setOpen(false)} portalContainer={host}>
        <p>Theme-aware content</p>
      </Modal>
      <div ref={setHost} />
    </section>
  )
}
```

Keep portal containers outside transformed or clipping ancestors; cross-document iframe
portals are unsupported. Tooltip content is descriptive and non-interactive.

## Fonts

Fonts are optional and the library stylesheet makes no network font requests. Space Grotesk
falls back to Archivo/Arial, Archivo to Helvetica Neue/Arial, and Space Mono to the system
monospace. Self-host licensed files with `@font-face` and set `--bui-font-display`,
`--bui-font-sans`, and `--bui-font-mono`, or use your existing application fonts. The showcase
separately opts into Google Fonts.

## Migration and support limits

`Switch` now forwards a native `HTMLInputElement` ref instead of an `HTMLButtonElement`.
Update ref types and private DOM assumptions. `Progress` forwards its ref and DOM props to
the actual `role="progressbar"` element, not the label/layout wrapper. Native uncontrolled
form reset restores defaults; controlled inputs require the caller to reset state.

Packed fixtures test React 18.3.1 and 19.2.4 with real rendering, SSR, native forms and
overlays. Automated tests and axe scans do not certify every browser, screen reader,
forced-color mode or OS preference. Consult the local `docs/release-verification.md` for
the exact executed scope and `docs/compatibility.md` for RHF, Next.js and portal examples.
Pre-1.0 minor versions may contain documented API, DOM or ref changes.

## Product examples

<a href="./?path=/docs/examples-settings--docs" target="_top">Workspace Settings</a> composes a
complete Profile/Notifications/Team flow: async load/save, field validation, retry without losing
edits, unsaved-change confirmation, search and empty states. The standalone preview is available
at <a href="../examples/settings/" target="_top">the Settings example</a>.

The local preview adds optional Button `intent="primary|secondary|destructive"`, inherited
`data-bui-density="compact|comfortable"`, and `keepMounted` on TabsContent/AccordionContent.
Existing defaults stay compatible. Retained panels keep their effects running; API adapters should
honor AbortSignal. The standalone example stores demo settings in versioned browser storage.
